# Камеры ViKi → Hybrid Retargeting → пальцы DG5F

Режим `live-hand` соединяет существующую онлайн-оценку ViKi с готовым
ретаргетингом из твоего `hand_hybryd_retargeting`. Oculus и UR10e в нём
не участвуют. Доступны кинематический preview, mock servo и физический
Tesollo backend через прежний SDK/servo/current/contact слой. Аппаратный
запуск этой новой интеграции ещё не проверен на стенде.

```text
синхронные RGB-D камеры / причинно проигрываемая запись
    → LiveHandEstimator: 21 наблюдаемая XYZ-точка, метры, rig frame
    → прежний landmarks_to_mano
    → прежний Vector + ограниченная коррекция DexPilot у кончиков
    → 20 суставных целей DG5F
    → кинематический просмотр DG5F в MuJoCo
```

Плотное облако сцены не подаётся в finger solver: ему нужны те же 21 точки
кисти, которые видны поверх облака в ViKi. Этот путь не читает офлайн
`cln.npz` / `plan.h5` и не достраивает скрытые пальцы экспериментальной
анатомической моделью. При отсутствии любой из 21 точки новый target
отклоняется, просмотр держит предыдущую позу. Старый target не воспроизводится
после истечения TTL 250 мс. При возвращении полной кисти история solver
сбрасывается; модель снова следует новым точкам.

## Что переиспользуется

Берётся уже имеющийся ROS-free `dg5f_camera_demo/src/dg5f_demo/retarget.py`.
Исходный Hybrid, MANO, 20-суставный порядок, scaling 1.2, joint limits,
ограничения distal hyperextension и fault map `rj_dg_5_1=0` остаются в том
проекте. ViKi подключает его через адаптер, а не создаёт второй Hybrid.
Ветка DexPilot включается при расстояниях thumb–finger меньше 55 мм и
доходит до своего максимального веса 0.8 при 25 мм. Это геометрическая
коррекция захвата, не измерение физического контакта или силы.

Внешний каталог монтируется только для чтения; никаких изменений в нём не
требуется. Без него `live-hand` сообщает об отсутствующем source, а не
подменяет ретаргетинг. Кодовые/YAML/URDF hashes записываются в session.json.
Среда ViKi использует Pin 4.1; алгоритм solver остаётся исходным.

По умолчанию ожидается соседняя папка:

```text
work/
  ViKi_inference/
  hand_hybryd_retargeting/dg5f_camera_demo/
```

Если она лежит иначе, задать абсолютный путь `DG5F_HYBRID_ROOT` к
**dg5f_camera_demo**, не к корню ROS workspace, во всех командах Compose:

```bash
export DG5F_HYBRID_ROOT=/полный/путь/hand_hybryd_retargeting/dg5f_camera_demo
```

## Сначала посмотреть запись

Из корня ViKi:

```bash
docker compose build live-hand
docker compose run --rm live-hand live-hand \
  --reference data/datasets/40mm-pnp/2026-10-06_11-15-00 --gui
```

Запись идёт в реальном времени ×1, автоматически заканчивается вместе
с источником. В окне MuJoCo можно вращать камеру мышью; закрытие окна
завершает сессию. Ctrl+C тоже останавливает её. X11 должен быть настроен
как для обычного MuJoCo preview в SETUP_GUIDE.

Без окна, с сохранением видео:

```bash
docker compose run --rm -e MUJOCO_GL=egl live-hand live-hand \
  --reference data/datasets/40mm-pnp/2026-10-06_11-15-00 --video
```

Путь к новой сессии печатается при старте. В ней:

- `hand.jsonl` — входные 21 точки, маски, времена и качество;
- `targets.jsonl` — 20 целевых углов в радианах, веса Hybrid, семь
  межпальцевых расстояний, валидность/причина отказа и время retarget;
- `preview.jsonl` — фактически показанные углы и исходная sequence;
- `session.json` — настройки, зависимости исходного Hybrid, hashes и счётчики;
- `preview.mp4` / `preview.png` — если указан `--video`.

В просмотре используются `mj_forward` и суставные пределы XML. Возможные
выходы Hybrid за эти пределы обрезаются явно; число таких суставов записано
в `preview.clipped_joints`. Это сумма срабатываний по показанным targets,
не число разных суставов. Она не скрывается в исходных targets.
Захват предмета, усилия и устойчивость контакта таким просмотром не проверяются.

## Управлять пальцами с настоящих камер

Нужны обе Kinect с прежней исправной разводкой USB/sync и та же активная
калибровка, что у reference. Перед запуском освободить камеры от другого
процесса ViKi; standalone session владеет ими сама. Reference даёт
геометрию/настройки камер, движение берётся из текущих кадров.

```bash
docker compose run --rm live-hand live-hand \
  --reference data/datasets/40mm-pnp/2026-10-06_11-15-00 \
  --source cameras --seconds 300 --gui
```

Показывать правую кисть обеим камерам. Разгибание/сгибание пальцев управляет
моделью; сближение большого и указательного включает прежнюю коррекцию pinch.
Начать с раскрытой ладони и медленного pinch, затем попробовать сгибание
каждого пальца, поворот ладони и её краткую потерю. При потере поза модели
держится; по возврату допустимых точек она продолжает следование.

Профиль этого finger-only режима: perception 15 Гц, One Euro min cutoff
2 Гц / beta 30, quality power 0, дополнительный joint low-pass Hybrid=1.
Настройки прежнего UR-режима не меняются. Параметры доступны через
`--perception-hz`, `--filter-beta`, `--input-ttl`, `--seconds`.
Дисплей получает только последнее состояние и не задерживает observation
очередью кадров; при тяжёлом software rendering промежуточные targets
могут не попасть на экран. Это видно по targets против preview.

## Аппаратная рука

Для физической DG5F добавлен отдельный image. Сначала собрать базовый
`live-hand`, затем SDK image. SDK берётся из того же read-only
`DG5F_HYBRID_ROOT/vendor/tesollo_control`. Native wrapper, vendor library и
исходный control runtime переиспользуются, а не переписываются.

```bash
docker compose build live-hand
docker compose build live-hand-hardware
```

Адрес руки из прежнего проекта — **169.254.186.72:502**, slave ID 1.
Это адрес DG5F, не адрес UR10e. Подключить Ethernet к контроллеру руки.
На выбранном проводном интерфейсе нужен адрес той же сети, например
`169.254.186.10/16`; для временной настройки:

```bash
ip -brief link
sudo ip link set <проводной_интерфейс> up
sudo ip addr add 169.254.186.10/16 dev <проводной_интерфейс>
ip route get 169.254.186.72
ping -c 3 169.254.186.72
```

Не добавлять адрес повторно, если он уже настроен. Маршрут должен идти по
этому Ethernet. Если IP руки изменён, передать актуальный через `--hand-ip`.
Остановить прежнее DG5F-приложение, чтобы SDK имел одного владельца.
Подключить обе Kinect и sync как в SETUP_GUIDE; освободить их от другого
процесса ViKi. Запуск из корня ViKi:

```bash
docker compose run --rm live-hand-hardware live-hand \
  --reference data/datasets/40mm-pnp/2026-10-06_11-15-00 \
  --source cameras --backend tesollo --execute \
  --hand-ip 169.254.186.72 --seconds 300 --gui
```

`--execute` разрешает подключение, но запуск остаётся **DISARMED**.
В терминале этой команды:

- `a` + Enter — ARM: проверка telemetry/readiness и начальная команда
  **из измеренной позы**, без команды раскрытия или перехода в home;
- `d` + Enter — DISARM и остановка low-level keepalive;
- `r` + Enter — явный RECOVER SDK, после него снова DISARMED;
- `q` + Enter, Ctrl+C или закрытие окна — завершение и отключение SDK.

При исправном hardware ARM допустим без наблюдаемой кисти: остаётся
TRACKING_HOLD. При свежих полных 21 точках — ACTIVE; при потере/старении
кадра — TRACKING_HOLD, без продолжения старого target. Возврат наблюдения
возобновляет следование без второго ARM, как в исходном проекте. Аппаратный
FAULT сам не снимается. Если ARM/recovery отклонены, причина печатается.

Сервоконтур — 60 Гц, исходный ServoController 120°/с / 720°/с², прежние
current/contact/lead ограничения и неисправный `rj_dg_5_1=0`. Эти ограничения
не подменяют проверку стенда. Все backend-вызовы принадлежат отдельному
процессу; inference и rendering не вызывают SDK. TTL 250 мс вычисляется
от **времени кадра**, а не от получения команды сервоконтуром. Автоматический
ARM и проигрывание записей физическим backend запрещены этим CLI.

В режиме с контроллером MuJoCo показывает **измеренные SDK углы**, а цели
по-прежнему лежат отдельно в `targets.jsonl`. Дополнительные артефакты:
`executor/servo.jsonl` — каждый servo cycle с telemetry/guard/состояниями;
`executor/final.json` — итоговое состояние и подтверждение отключения SDK.
Если отключение не подтверждено, сессия завершается с ошибкой.

Без hardware ту же цепочку можно проверить на записи:

```bash
docker compose run --rm live-hand-hardware live-hand \
  --reference data/datasets/40mm-pnp/2026-10-06_11-15-00 \
  --backend mock --auto-arm --gui
```

`--auto-arm` доступен только mock. Его результаты не подтверждают усилия,
контакт или стабильность физической руки. Протокол проверки и ограничения:
[аппаратная интеграция](2026-10-19-dg5f-servo-integration.md).
