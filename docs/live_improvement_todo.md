## 1. Онлайн-ретаргетинг: уменьшить отставание TCP

- [ ] Зафиксировать одну последовательность целей с исходными временами
  доступности; одинаковые initial q, binding, scale, модель и лимиты для всех
  вариантов. Не запускать perception заново для каждого варианта IK.
- [ ] Сохранить воспроизводимый baseline с текущим position gain 6 s⁻¹.
- [ ] Сравнить position gain 6 / 10 / 15 s⁻¹ в MuJoCo.
- [ ] Отдельно сравнить damping и регуляризацию изменения скорости;
  не ослаблять floor/collision/скоростные/ускорительные ограничения.
- [ ] Проверить ограниченную feed-forward скорость цели, вычисляемую только
  по уже доступным наблюдениям. Сохранить source timestamps и TTL; не
  продолжать предсказанное управление после потери валидного наблюдения.
- [ ] Измерить mean/RMSE/p95/max TCP error, остаточное движение на остановках,
  скорость/ускорение, насыщение ограничений, модельные зазоры и время решения.
- [ ] Проверить победителя на дополнительных записях и резких сменах
  направления. Улучшение на одном эпизоде не считать общим результатом.
- [ ] Зафиксировать результаты и выбрать настройки; отдельно отметить,
  какие изменения проверены только в симуляции.

## 2. Причинное сглаживание: дрожание ↔ задержка

- [ ] Записать неподвижную кисть, медленное движение, быстрое движение,
  смены направления и частичные перекрытия.
- [ ] Сравнить сочетания One Euro `min_cutoff` и `beta` при неизменном IK.
  Текущая отправная точка: 2 Hz / 0.5, derivative cutoff 1 Hz.
- [ ] Оценить дрожание на неподвижных участках и программное запаздывание
  фильтра относительно входных оценок; последнее не является абсолютной
  camera-to-actuator latency или ground-truth accuracy.
- [ ] Сравнивать движение человека, filtered target и measured TCP совместно:
  замедление цели не выдавать за повышение точности всей системы.

## 3. Анатомическая стабилизация всех пальцев

- [ ] Получать длины костей из причинной начальной калибровки пользователя.
- [ ] Добавить покадровую согласованную модель кисти с устойчивыми длинами
  костей и допустимыми суставными углами вместо независимых 21 точек.
- [ ] Использовать качество геометрии как вес наблюдений и явно сохранять
  маски наблюдаемых/восстановленных точек.
- [ ] Измерить вариации длин костей, reprojection residual, дрожание кончиков,
  стабильность palm orientation и дополнительную стоимость вычислений.
- [ ] Отдельно оценить эффект на pinch/orientation и на будущую гуманоидную
  руку; не предполагать такое же улучшение TCP в режиме wrist-only.

## 4. Качество наблюдений и восстановление после потерь

- [ ] Использовать согласованность камер, residual и геометрию лучей для
  управления весом измерения/силой фильтрации; handedness score не принимать
  за уверенность каждой 3-D точки.
- [ ] Пересоздавать опору ориентации после длительной потери по нескольким
  свежим согласованным наблюдениям; не застревать на старом rotation gate.
- [ ] Проверить короткие/долгие пропуски, большие повороты, вырожденную ладонь,
  повторные кадры и возврат кисти в кадр.
- [ ] Сохранить ручной rebind после потери: восстановление оценки само по
  себе не возобновляет движение физического робота.

## Общие правила сравнения

- [ ] Сохранять входы, hashes, параметры и результаты каждого эксперимента.
- [ ] Разделять качество perception, задержку фильтра и слежение контроллера.
- [ ] Не менять frozen perception profiles и защищённые baseline artifacts.
- [ ] Перед аппаратным тестом отдельно проверить реальные оси, TCP, payload
  и регистрацию стенда; симуляция этого не подтверждает.
